## 1. 项目用途与选择原因

uv 是 Astral 团队用 Rust 编写的 Python 包与项目管理器，目标是用一个工具替代 `pip`、`pip-tools`、`pipx`、`poetry`、`pyenv`、`twine`、`virtualenv` 等多个工具。它提供依赖解析与安装、项目与虚拟环境管理、通用锁文件（`uv.lock`）、Python 版本安装、脚本内联依赖运行，以及兼容 pip 的命令行接口，官方基准称其安装速度比 pip 快 10—100 倍。主要用户是需要频繁创建环境、在 CI 中复现依赖的 Python 开发者、数据科学与教学场景。

选择它的原因有两点：一是本课程第 3 讲以 uv 作为依赖管理实践工具，我按课程内容实际使用过 `uv init`、`uv add`、`uv sync`，对它的工作方式有直观体会；二是它同时涉及 Rust 实现与 Python 生态，仓库结构、贡献流程都比较完整，适合作为调研对象。本次调研只阅读仓库资料，未安装或修改项目代码。

uv 采用 **MIT 或 Apache-2.0 双许可证**，使用者可任选其一，仓库根目录分别提供 [LICENSE-APACHE](https://github.com/astral-sh/uv/blob/main/LICENSE-APACHE) 和 [LICENSE-MIT](https://github.com/astral-sh/uv/blob/main/LICENSE-MIT)，README 的 License 一节也写明了这一点。

需要注意的义务：无论选择哪个许可证，再分发时都必须保留原版权声明和许可证文本；若选择 Apache-2.0，修改后的文件需要标注修改说明，并且该许可证包含专利授权条款，若使用者就本项目提起专利诉讼，授权将终止。另外，许可证只授予代码版权，不授予 Astral 的商标使用权，不能暗示官方背书。
